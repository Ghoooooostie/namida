- Dart 限制：方法签名 **不能同时有 `[...]` 位置参数和 `{...}` 具名参数**（否则 `expected_token`）。
  因此 method 只用 8 个可选位置参数；调用点传具名参数会在后续轮次以 `undefined_named_parameter` 报出，需手工删掉该忽略参数。

## 启动红屏 `LateInitializationError: Field '_audioHandler' has not been initialized`（已修）
崩溃链（见 `debug/device_logs_20261003.txt` 14:36 与 14:44 两条）：
`MainPageWrapper.initState` → `MiniPlayerController.inst` → `Player.currentIndex` → `Player._audioHandler`（`late`）。

根因是**启动流程被 stub 层打断**，不是 UI 问题：
1. YouTube 已被 stub（`lib/youtube/_stubs_base.dart`，成员一律 `=> null`）。
2. 旧代码 `YoutubeInfoController.initialize(completer).catchError(...)` 对 `null` 调方法 → 同步 `NoSuchMethodError`，
   而该行位于 `await Player.inst.initializePlayer()`（原 288 行）**之前**且同处一个 `try`，
   于是播放器初始化被整段跳过 → 之后 UI 一构建就红屏。
3. 同类问题：`YoutubeInfoController.utils.fillBackupInfoMap()` 在 stub 下 `utils == null`，
   它在 `_secondaryAppInitialization` 的 `await [...]` 列表里，抛错会让**列表里其余全部初始化被跳过**。
4. 隐藏的第二个坑：`ytInfoInitSyncItemsCompleter` 只有真实 YT 初始化才会 complete；
   stub 下永挂 → 启动 `await` 列表里的 `ytInfoInitSyncItemsCompleter.future` 死等 → UI 永远不构建（卡启动）。

改动（`lib/main.dart`、`lib/controller/player_controller.dart`）：
- 把 `ytInfoInitSyncItemsCompleter` / `prepareLatestQueue` / `args` 的声明**提到 try 之外**，
  并把 `Player.inst.initializePlayer()` 移出那个大 try，单独 try/catch —— 任何无关失败都不许跳过播放器初始化。
- YT 初始化改为 `is Future` 判断 + `finally` 里兜底 `completer.complete()`（stub 下也能走完启动）。
- `utils.fillBackupInfoMap()` 移出列表，改为 `utils != null` 判空 + `is Future` 判断。
- `Player` 增加 `isInitialized`（在 `initializePlayer` 赋值 `_audioHandler` 处置 true），未初始化时写日志。
- `flutter analyze` 这两个文件：0 error / 0 warning（仅 2 条既有 `unnecessary_import` info）。

**约定（重要）**：精简构建里凡是链式调用 stub 成员（`.catchError` / `await` / `.then`）的地方都会 NPE，
必须先判空/判 `Future`；stub 返回 null 在 `await [ ... ].whereType<Future<void>>()` 里反而是安全的。
